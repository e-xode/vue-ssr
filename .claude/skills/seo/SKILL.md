# SEO — Vue SSR Starter Kit

> Every public page is fully server-rendered with meta, structured data, and hreflang so it ranks and earns rich results. SEO copy lives in i18n; the wiring lives in `src/ssr/head.js` (called by `entry-server.js`) and `src/api/http/seo.js`. There is **no `seo.config.js`** — meta is driven by route `meta` keys, not a central config file.

## Division of responsibilities

| Concern | Skill |
| --- | --- |
| Product facts: stack, features, differentiator, license, assets | marketing-content |
| page meta/structured data | seo |

## How SEO is wired

| Layer            | Where                          | Responsibility                                                              |
| ---------------- | ------------------------------ | --------------------------------------------------------------------------- |
| Route metadata   | `src/router.js`                | `meta.title` / `meta.description` / `meta.keywords` (i18n keys), `meta.robots`, `meta.statusCode` |
| SSR injection    | `src/ssr/head.js`              | `generateHead()` builds the full `<head>` per route (meta, canonical, hreflang, OG/Twitter, JSON-LD), called from `src/entry-server.js` |
| Meta copy        | `src/translate/{en,fr}.json`   | the `meta.*` strings resolved via `t()` — edit copy here (via the translate agent) |
| robots / sitemap | `src/api/http/seo.js`, `src/shared/sitemap.js`, `src/shared/seoConstants.js` | dynamic `robots.txt` + `sitemap.xml` (NOT static files) |
| Localized slugs  | `src/shared/localizedRoutes.js` | `PAGES`: the indexable pages, one slug per locale; drives sitemap, hreflang and the 301 redirects |

Meta resolution: `resolvePageMeta(route, t)` reads `route.meta.title/description/keywords` as i18n
keys and resolves them with `t()`. The page title renders as `${pageTitle} — ${APP_NAME}` (`buildTitle()` in `src/shared/title.js`, also used on the client for `document.title`).

## Hard rules

1. **`robots.txt` and `sitemap.xml` are generated by the server (`src/api/http/seo.js`)** — never add static copies under `public/`.
2. **Every public page** gets: a unique title + meta description, a canonical, OG + Twitter tags, and hreflang alternates for `en` and `fr` plus `x-default` pointing at the `en` URL.
3. **404 pages carry no canonical and no hreflang** — driven by `route.meta.statusCode === 404` (the `is404` branch in `src/ssr/head.js`).
4. **Non-indexable routes** (signup, signin, verify-code, forgot/reset-password, dashboard, account, admin) set `meta.robots: 'noindex, ...'` and are `Disallow`ed in `robots.txt` (`ROBOTS_DISALLOWED_PATHS` in `seoConstants.js`). JSON-LD is suppressed when `meta.robots` includes `noindex`.
5. **Meta title/description/keywords text lives in i18n** (`meta.*` keys) — edit copy via the `translate` agent, never hardcode it in `src/ssr/head.js`.

## JSON-LD structured data (already emitted)

`getSchemaMarkup()` in `src/ssr/head.js` emits, for indexable routes only:

- **Organization** — site-wide (name = `APP_NAME`, `url`, `logo`, `sameAs` from `SOCIAL_FACEBOOK` / `SOCIAL_INSTAGRAM` / `SOCIAL_TELEGRAM` env vars).
- **WebSite** — on the `Index` route.
- **BreadcrumbList** — on pages with more than one breadcrumb (home plus at least one titled segment).

Optional enhancements (not currently emitted — add deliberately if a page warrants it):
`SoftwareApplication` (to describe the kit as a product), `FAQPage`, `Person`. Validate any
structured-data change with Google's Rich Results Test.

## Open Graph, Twitter, and head extras

`generateHead` also emits: OG (`og:title/description/url/type=website/site_name/image` 1200×630
`/og-image.png` + `og:image:alt` + `og:locale` + `og:locale:alternate`), `fb:app_id` (when
`FACEBOOK_APP_ID` is set), Twitter `summary_large_image`, `theme-color` (theme-dependent), `author`
(= `APP_NAME`), apple-touch-icon, favicons, and the web manifest.

The head also exposes `<meta name="ga-id">` and `<meta name="recaptcha-site-key">` (from `GA_MEASUREMENT_ID` / `RECAPTCHA_SITE_KEY`, when well-formed) and preloads the Inter font; client code reads those metas.

Environment inputs: `NODE_HOST` (canonical/site URL; must be a public https origin in production, `http://localhost:<NODE_PORT>` in dev), `APP_NAME`,
`FACEBOOK_APP_ID`, `SOCIAL_*`. Locales come from `LOCALE_CODES` (`en`, `fr`) in `src/shared/const.js`.

## Sitemap coverage (`src/shared/sitemap.js`)

Public, indexable URLs only - one `<url>` per locale with hreflang alternates, `<lastmod>` (when an
entry has one), `changefreq`, and `priority`:

- Entries come from `PAGES` in `src/shared/localizedRoutes.js` (today `Index` and `Contact`): home
  (priority 1.0) and contact (0.8), each in `en` and `fr`, with `x-default` pointing at the `en` URL.
  Cached in memory (1h TTL), served with `Cache-Control` and `Last-Modified`.
- `getDynamicSitemapEntries()` is the hook for database-backed URLs (returns none today); a failure
  there is logged and the static entries are still served.
- All auth/account/admin/dashboard paths and `/api/` are `Disallow`ed in `robots.txt`.
- When you add a new **public, indexable** page, add it to `PAGES`, build its route with
  `pageRoute(name)` in `src/router.js`, and give it `meta.title`/`meta.description` i18n keys.
  `PAGES` is isomorphic code shared by the router, redirects, head and sitemap.

## Per-page SEO checklist

1. Route has `meta.title` + `meta.description` keys (and `meta.keywords` if relevant), present in both locales.
2. Canonical resolves to the absolute `NODE_HOST` URL for the current locale (auto, except 404).
3. hreflang `en` / `fr` / `x-default` present (auto, except 404).
4. OG image + type + Twitter card present (auto via `generateHead`).
5. Indexable? then it is in `PAGES`. Not indexable? then `meta.robots: 'noindex, ...'` and `Disallow`ed.
6. Appropriate JSON-LD emitted (Organization always; WebSite on home; BreadcrumbList on deep pages) and validated.

## Performance is SEO

Core Web Vitals affect ranking. The kit already favors SSR with hydration, self-hosted fonts
(`@fontsource-variable/inter`, `@fontsource/ibm-plex-mono` — no render-blocking Google Fonts), lazy-loaded
routes, and `compression`. Flag regressions as ➜ delegate to design (visual/CSS) or note for the
orchestrator (code). ➜ See skill: vue3-performance for client/runtime perf, vue-ssr-deployment for build.
